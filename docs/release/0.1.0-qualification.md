## Remaining release blocker

0.1 remains `NOT RELEASE READY`. The normal branch version authority and release pipeline are now defined, but the **final `0.1.0` workflow has not yet been executed from the frozen `main` release commit**.

Before changing this verdict:

1. Integrate the stacked release work into `main` in dependency order and freeze the actual release commit.
2. Dispatch the manual release workflow from that exact commit with `version=0.1.0` and the full frozen `expected_sha`.
3. Build one deterministic framework-dependent portable ZIP and record its SHA-256/manifests.
4. Download and verify that same exact archive on Ubuntu, Windows and macOS; require PackagedE2E GREEN on all three and the Codex reference-host lifecycle GREEN on Linux.
5. Only after the platform matrix is GREEN, generate and verify GitHub Artifact Attestations/Sigstore provenance for that exact ZIP.
6. Re-run/confirm frozen-main release gates, record the final archive SHA/provenance/run IDs here, then change this record to `READY` and create the release/tag.

If any additional host is promoted from `documented compatible` to `Qualified`, that host must first receive its own executable smoke evidence. This is conditional scope, not a blocker for the Codex-reference-host 0.1 release.

No host or release status may be promoted by editing this document alone; corresponding executable evidence must exist first.
