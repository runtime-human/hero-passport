## Release blockers

0.1 remains `NOT RELEASE READY` until the remaining release-blocking evidence is closed:

1. Prove the accepted Codex packaged lifecycle through the actual reference host: `bootstrap → start → finish → restart → context → replay`, with one persistent Hero Passport data root and explicit project binding across the host restart.
2. Run the release platform matrix required by `docs/MVP-PR-PLAN.md` on standard GitHub-hosted Linux, Windows and macOS runners. The normal PR loop should remain Linux-first; cross-platform qualification should stay narrowly scoped to release evidence rather than duplicating the full Linux suite on every commit.
3. Run exact-host smoke for every additional host that the 0.1 release chooses to advertise above documented compatibility.
4. Produce the final versioned release artifact from the frozen release commit, record its checksum/signing evidence where available, and run final exact-artifact qualification before changing this verdict.

No host status may be promoted by editing this document alone; the corresponding executable evidence must exist first.
