## Release blockers

0.1 remains `NOT RELEASE READY` until the remaining release-blocking evidence is closed:

1. Run a real current stable Codex CLI against the packaged artifact in an isolated project and record exact Codex version/OS/date.
2. Prove at minimum Codex native MCP registration/listing and project Skill discovery/configuration; preferably prove Codex actually launches/connects the packaged STDIO server rather than merely accepting configuration.
3. If Codex is to be labeled `Qualified`, record the host-level lifecycle evidence required by `docs/integrations/CODEX.md`, including tool discovery, project binding, recovery and conservative Skill behavior.
4. Run exact-host smoke for every additional host that the 0.1 release chooses to advertise above documented compatibility.
5. Produce the final versioned release artifact, record package checksum/signing evidence where available, and run final exact-artifact qualification before changing this verdict.

No host status may be promoted by editing this document alone; the corresponding executable evidence must exist first.
