## Remaining release blocker

0.1 remains `NOT RELEASE READY` because the current branch still identifies itself as `0.1.0-dev` and the final distributable has not yet been qualified as an immutable release artifact.

Before changing this verdict:

1. Integrate/freeze the actual release commit so the candidate is no longer a moving stacked-PR head.
2. Produce the final versioned `0.1.0` distributable from that exact commit using one authoritative product version.
3. Record SHA-256 for the exact archive and attach verifiable build provenance. For the public repository, GitHub Artifact Attestations/Sigstore are the preferred no-private-key provenance mechanism, subject to a final release-time documentation check.
4. Extract and execute qualification against that exact archive rather than a separate publish directory, then verify the provenance/checksum before release publication.
5. Re-run the release gates on the frozen release commit and only then change this record to `READY` and create the release/tag.

If any additional host is promoted from `documented compatible` to `Qualified`, that host must first receive its own executable smoke evidence. This is conditional scope, not a blocker for a Codex-reference-host 0.1 release.

No host or release status may be promoted by editing this document alone; corresponding executable evidence must exist first.
